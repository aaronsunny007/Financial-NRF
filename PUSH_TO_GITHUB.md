# Pushing this to GitHub

Four files were added to your project folder: `.gitignore`, `README.md`,
`requirements.txt` and `LICENSE`. Nothing existing was changed or deleted.

**Read the warning at the bottom before you run anything.**

---

## Step 1 — open a terminal in the project folder

Press `Win`, type `cmd`, press Enter, then:

```
cd C:\Users\denny\Financial-NRF
```

## Step 2 — check that the exclusions are working

This is the step that matters. Run it and read the output.

```
git init
git add .
git status --short | find /c /v ""
```

That last command prints **how many files** would be committed. You want a number
in the low hundreds. If it prints something in the thousands, `venv` is being
included — stop and tell me rather than continuing.

Then confirm the big folders are excluded:

```
git status --short | findstr /i "venv models embeddings vector_db train.json"
```

**This should print nothing at all.** If it prints anything, stop.

## Step 3 — commit

```
git commit -m "Numerical Reliability Framework for RAG-based financial QA"
```

## Step 4 — create the repository on GitHub

Go to https://github.com/new and make an empty repository called
`Financial-NRF`. Do **not** tick "Add a README", "Add .gitignore" or
"Choose a license" — you already have all three.

Decide public or private now. See the warning below.

## Step 5 — push

Replace `YOUR-USERNAME` with your GitHub username:

```
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/Financial-NRF.git
git push -u origin main
```

Windows will open a browser window to sign you in to GitHub the first time.

---

## Before you make it public

**Check your university's rules on publishing dissertation code before submission
or before your result is confirmed.** Some institutions treat a public repository
as publication, and some plagiarism checks flag your own public code against your
own submission. If you are unsure, create it **private** — you can switch it to
public later in Settings, and switching that way round is trivial.

## What is deliberately not in the repository

| Excluded | Why |
|---|---|
| `venv/` | About 1 GB of installed packages. Rebuilt from `requirements.txt`. |
| `data_loader/*.json` | FinQA data. `train.json` alone is 78 MB; GitHub flags files over 50 MB. Publicly downloadable from the FinQA repository. |
| `models/`, `embeddings/`, `vector_db/` | Downloaded weights and generated caches. Regenerated by the pipeline. |
| `*.zip`, `__pycache__/` | Build artefacts. |

The `results/` CSVs **are** committed on purpose — they are what lets anyone trace
every figure in your report back to the individual answers it came from.

---

## If something goes wrong

**"src refspec main does not match any"** — the commit in step 3 did not happen.
Run `git log --oneline` to check.

**A push is rejected for file size** — something large slipped past the exclusions.
Run `git reset` to undo the staging, tell me what the error named, and I will fix
the `.gitignore`.

**The push hangs or asks for a password** — GitHub no longer accepts account
passwords over HTTPS. Let the browser sign-in window handle it, or install GitHub
CLI (`winget install GitHub.cli`) and run `gh auth login` first.
